# AI 护栏规则

> 本文档定义 AI 的行为边界，AI 必须严格遵守。

---

## 核心原则

**AI 只做被明确要求的事情，不做任何假设或预设。**

---

## ✅ AI 可以做的事情

| 允许 | 条件 |
|------|------|
| 创建/修改代码 | 用户明确要求，且有 spec 文档支撑 |
| 创建 CSV 数据表 | 用户确认了数据结构设计后 |
| 创建新的 spec 文档 | 用户要求定义某个系统/规范时 |
| 修复 Bug | 用户指出问题并要求修复 |
| 重构代码 | 用户明确要求重构 |
| 生成目录结构 | 仅创建空目录占位，不预填内容 |

---

## ❌ AI 禁止做的事情

| 禁止 | 原因 |
|------|------|
| 预设游戏玩法设计 | 玩法需用户主导设计 |
| 假设数据表结构 | 数据结构需用户确认 |
| 自行添加示例数据 | 示例数据容易误导 |
| 引入未讨论的系统 | 如擅自创建"技能系统"、"房间系统" |
| 预设枚举值/常量 | 如 SkillType.Melee 等具体值 |
| 做"好玩/难易度"评价 | 用户明确不需要 |

---

## 工作流程约束

### 1. 创建新功能前

```
用户请求 → AI 确认范围 → 用户确认 → AI 执行
```

**示例对话**：
- 用户：帮我实现技能系统
- AI：请先确认技能系统的设计范围：
  - 技能有哪些属性？
  - 技能类型有哪些分类？
  - 需要我先出 spec 文档吗？
- 用户：[确认设计]
- AI：[开始实现]

### 2. 无法完成时

**说明原因，不猜测**：
- ✅ "这个功能需要先定义 XXX，请确认设计后我再实现"
- ❌ "我假设 XXX 是这样的..."（然后自行实现）

### 3. 发现遗漏时

**询问，不补充**：
- ✅ "我注意到缺少 XXX 的定义，需要我帮您创建吗？"
- ❌ "我发现缺少 XXX，已经帮您补充了"

---

## 边界划分

### 基础框架（AI 可自行创建）

- 单例基类/模式
- 事件中心（通用结构）
- 文件目录结构（空目录）
- .gitignore
- 代码规范文档
- Git 工作流文档

### 业务设计（需用户确认）

- 具体 Manager 的实现（如 RoomManager 内部逻辑）
- 数据表结构（CSV schema）
- 枚举定义（如技能类型、房间类型）
- 游戏数值
- 具体玩法逻辑

---

## 违规处理

如果 AI 违反了上述规则：

1. 用户指出问题
2. AI 立即删除/撤销相关内容
3. AI 回到正确的工作流程
