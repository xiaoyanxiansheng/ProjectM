# AI 护栏规则

> 本文档定义 AI 的行为边界，AI 必须严格遵守。

---

## 核心原则

**AI 只做被明确要求的事情，不做任何假设或预设。**

---

## 🚨 会话启动检查（强制）

每次新会话开始时，AI 必须先阅读以下文档：

| 文档 | 路径 |
|------|------|
| 系统架构 | `spec/architecture.md` |
| 编码规范 | `spec/coding-standards.md` |
| 本文档 | `spec/ai-guardrails.md` |

### 技术栈速查

| 项目 | 值 |
|------|-----|
| 引擎 | Unity 6.3 LTS |
| 渲染管线 | URP |
| 输入系统 | 新 Input System |

---

## 📋 功能开发流程（强制）

```
Step 1: 用户提供设计
    ↓
    用户在 design/ 目录创建设计文档，或直接描述需求
    ↓
Step 2: AI 生成 Spec
    ↓
    AI 根据用户设计，在 spec/features/ 生成规范化文档
    ↓
Step 3: 用户确认 Spec
    ↓
    用户明确说"确认"后才能继续
    ↓
Step 4: AI 生成代码
    ↓
    代码中包含调试日志（Debug.Log）
    ↓
Step 5: AI 自检
    ↓
    检查：编译错误、组件挂载、引用设置
    ↓
Step 6: 输出测试结论
    ↓
    明确：是否需要用户测试？如需，给出测试步骤
    ↓
Step 7: 用户测试（如需）
    ↓
    用户只需看 Console 输出 + 简单操作
    ↓
Step 8: 反馈与修复
    ↓
    有问题 → AI 修复 → 循环
    ↓
Step 9: 功能确认
    ↓
    AI 删除调试日志
    ↓
Step 10: AI 提交 Git
```

## 📁 文档目录结构

```
ProjectM/
├── design/                    # 用户的设计文档（用户写）
│   └── xxx.md                 # 自由格式，想法/草稿/设计
│
└── spec/                      # AI 整理的规范（AI 写）
    └── features/              # 功能 spec
        └── xxx.md             # 规范化格式，含验收标准
```

| 目录 | 作者 | 格式 | 内容 |
|------|------|------|------|
| `design/` | 用户 | 自由 | 想法、设计、草稿 |
| `spec/features/` | AI | 规范化 | 字段定义、验收标准 |

---

## 自检内容

| 检查项 | 方法 |
|--------|------|
| 编译错误 | 读取 Unity Console |
| 组件挂载 | 通过 MCP 检查 |
| 引用设置 | 通过 MCP 检查 |
| 预制体 | 确认存在且配置正确 |

---

## 测试结论格式

```
## 自检结果

| 检查项 | 状态 |
|--------|------|
| 编译 | ✅/❌ |
| 组件 | ✅/❌ |
| 引用 | ✅/❌ |

## 是否需要用户测试

[是/否] - [原因]

## 测试步骤（如需）

1. [具体操作]
2. [预期结果]
3. [如何判断成功/失败]
```

---

## ✅ AI 可以做的事情

| 允许 | 条件 |
|------|------|
| 根据 design/ 生成 spec | 用户要求时 |
| 创建/修改代码 | spec 确认后 |
| 创建 CSV 数据表 | spec 确认后 |
| 修复 Bug | 用户指出问题时 |

---

## ❌ AI 禁止做的事情

| 禁止 | 原因 |
|------|------|
| 预设游戏玩法设计 | 需用户在 design/ 定义 |
| 假设数据表结构 | 需用户在 design/ 定义 |
| 跳过 spec 直接开发 | 必须先生成 spec 并确认 |
| 跳过用户确认 | 必须等用户明确说"确认" |
